# Case Report Writer Pack, and an active PHI-stripping rule (not just a passive one)

The first real code for "A&I Research," PROJECT-BRAIN.md's other long-planned, empty domain Pack (alongside Medical Career Advisor, ADR 0009) — built the moment two real case reports needed drafting for the 2027 AAAAI Annual Meeting. Same shape as `career-advisor`: one draft-only Agent (`case-report-writer`), its behavior entirely in the system prompt, no new Core concepts, no submission capability (there is no submission Tool at all — the prompt can't imply otherwise because there's nothing to call).

**PHI handling here is a stronger, active rule than career-advisor's, on purpose.** Career-advisor's hard rule is passive: don't invent facts the user didn't give you. That's not strong enough for clinical case material, because the raw source here (chart review notes, a colleague's summary) is far more likely to have a patient name or MRN embedded in it than a resume fact is — a real one showed up in the very Google Doc this Pack was built to use. So `case-report-writer`'s prompt adds an active instruction: if a name, MRN, or other direct identifier appears in what the user gives it, strip it, replace it with a generic reference, and say so plainly near the top of the response — never silently pass it through, and never silently drop it without telling the user. This is a second layer, not a replacement for care upstream — the operator (this Claude Code session) still de-identifies before ever constructing a task, exactly as PROJECT-BRAIN.md Section 7 already requires ("avoid PHI... use de-identified or fictional cases").

**The 2027 AAAAI Annual Meeting facts are only partially verified, and the prompt says so.** A live search confirmed the real submission structure — a separate, later case-report track (due September 21, 2026) specifically for first-year fellows, medical students, and residents, distinct from the general abstract deadline (already past). Two attempts to fetch the actual formatting/word-limit page both failed (404/403). Rather than filling that gap with a plausible-sounding generic case-report format presented as AAAAI's actual rule, the prompt states the gap explicitly every time and tells the user to confirm current formatting against the live portal before submitting — the same discipline ADR 0009 already established for the Chrysalis letter-writer prompt: verified fact or an explicit "I don't know," never a confident guess in between.

**Not built here:** any second Agent, any parallel-execution mechanism in Core, or any co-author/submission workflow. Two case reports just means running this one Agent twice, once per patient, with different real facts each time — that's an ordinary use of the existing `orchestrator run`, not a reason to add new orchestration machinery.
