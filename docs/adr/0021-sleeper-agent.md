# Sleeper agent: read-only monitoring, gated GraphQL writes, and pick'em with no placement path

The owner plays Sleeper fantasy football and Sleeper Picks (pick'em). Sleeper exposes three different surfaces, and each gets a different level of trust.

**Reads use the documented public API** (`https://api.sleeper.app/v1`): users, leagues, rosters, matchups, transactions (including FAAB bids), drafts, `/players/nfl`, trending adds/drops and NFL state. It is read-only and needs no credentials. `src/integrations/sleeper/real-client.ts` calls it with `fetch` (ADR 0002) and throttles itself to 900 calls a minute, under Sleeper's stated ~1000. `/players/nfl` is about 15MB today (not the ~5MB often quoted), and Sleeper asks callers to fetch it at most once a day. It is cached in memory and in `.orchestrator/sleeper/players-nfl.json`, which is gitignored, and refetched after 24 hours. Two undocumented read endpoints the Sleeper app uses are also called: `/schedule/nfl/regular/<season>` (bye weeks) and `/projections/nfl/<season>/<week>` (projections). Both worked on 2026-09-25 but can change without notice, so every caller reports them as unavailable when they fail rather than failing the whole report or assuming nobody is on bye.

The owner supplies his Sleeper username at runtime. Every read Tool resolves it to a user id itself and never trusts an id from the model.

**Writes use Sleeper's private GraphQL endpoint** (`https://sleeper.com/graphql`), the one the web app uses. It is unofficial. The operation names and argument shapes (`roster_update_starters`, `roster_update_reserve`, `roster_update_taxi`, `league_create_transaction`, `submit_waiver_claim`, `cancel_waiver_claim`, `propose_trade`, `accept_trade`, `reject_trade`) come from the MIT-licensed community project joscaz/sleeper-mcp, which read them from the live schema by introspection. This project has never sent one. Every write goes through one gate, `runSleeperWrite`, which sends nothing unless `confirm` is exactly `true`. Without it, the call returns a dry-run preview: the plain-English effect, a check against the league's live rosters, and the exact GraphQL operation and variables. With it, the roster check is re-run, and any problem, or a missing roster check, blocks the write. The CLI exposes this as `orchestrator sleeper write --action <file>` (dry run) and `--confirm`. The agent gets a safe/consequential pair, as with Polymarket (ADR 0019): `sleeper-preview-write` never holds the write client, and `sleeper-execute-write` is `requiresApproval: true` with no way to turn that off, and also requires `"confirm": true` in its input. The only credential is the owner's own session token in `SLEEPER_TOKEN`. Email/password login, which sleeper-mcp supports, is deliberately not built: the agent should never hold the owner's password. With no token there is no write client, and no fake fallback, so nothing can claim a write happened.

**Sleeper Picks has no API at all**, documented or unofficial, so there is no placement path in this project, gated or otherwise. The pick'em module (`src/sleeper/pickem/`) researches a line the owner copies from the app against Sleeper's own projection, tracks the bankroll, and writes out the exact slip. The owner places every entry by hand. His staking rules are enforced in code: $15 starting bankroll; standard plays $3–$4; high-conviction plays up to 50% of the available bankroll, never 100%; at most 2 plays a day; weak lines (under 10% off the projection) are refused. Entries enter the ledger only when the owner logs them with `orchestrator sleeper pickem log`, which is CLI-only, so a model cannot record an entry he didn't make. A test checks that no pick'em source file does network I/O or exports a place/submit/enter function, and that no registered Tool has such a name.

Two agents keep the surfaces apart. `sleeper-manager` has the read Tools and the gated write pair. `pickem-researcher` has only the three pick'em Tools, none of which is consequential.

Not built: draft tools, league chat, trade-offer evaluation, waiver-claim edits, and any scheduled or unattended run. Pick'em research uses only Sleeper's projection, which the line setter also sees, so the agent says it has no guaranteed edge.
